# Rules for every coworker in this swarm

Read these before starting. Your controller (agent agent_muaw43cc_yghv5cv) integrates, tests, builds, commits and publishes the batch; you do not.

1. Never run `git commit`, `git push`, `git checkout`, `git stash` or `git reset`. Never revert or reformat lines you did not write.
2. Other agents' uncommitted work lives in the working tree. Do not modify these files unless your task names them, and then only with a small additive hunk you report explicitly: docs/local-models.md, scripts/fixtures/fake-claude.mjs, src/main/agent-control.ts, src/main/agent-control.test.ts, src/main/close-confirmation.ts, src/main/database.ts, src/main/index.ts, src/main/local-models/agent.ts, src/main/local-models/control-integration.test.ts, src/main/local-models/tools.ts, src/main/project-activity.ts, src/main/project-activity.test.ts, src/main/providers/adapter.ts, src/main/providers/claude.ts, src/main/providers/claude.test.ts, src/main/structured-sessions.ts, src/main/structured-sessions.test.ts, src/main/structured-store.ts, src/renderer/src/attention.ts, src/renderer/src/attention.test.ts, src/renderer/src/components/TabActivityIndicator.tsx, src/renderer/src/components/TabActivityIndicator.test.ts, src/renderer/src/panes/ProcessDashboardPane.helpers.ts, src/renderer/src/panes/StructuredAgentPane.tsx, src/renderer/src/styles.css, src/renderer/src/use-app-updates.ts, src/shared/models.ts, src/shared/structured-agent-reducer.ts, src/shared/structured-agent-reducer.test.ts, src/shared/structured-agent.ts, package.json, feature-list.md.
3. Stay inside your file ownership. If you need a change outside it, write down exactly what and why in your report instead of making it.
4. No window over the owner's screen. Any Electron launch uses `CONDUCTOR_TEST_USER_DATA` (the window parks off-screen) or an existing script under `scripts/`; never a bare `npm run dev`. Run at most one smoke script at a time; `npm.cmd run build` is needed before a smoke and takes about a minute.
5. Machine limits are in `docs/machine-profile.md`: 12 GB VRAM, one llama.cpp server at a time, no multi-gigabyte downloads and no system installs without the owner; propose the exact command instead.
6. Evidence, not claims: `npx tsc --noEmit` and the relevant `npx vitest run <files>` for code; a smoke or probe for anything the owner can see or anything about tokens, with the numbers in your report. Say plainly what you could not verify.
7. Keep the machine responsive: do not start long benchmarks on the local model while a native coworker is also using it; a single measured run is enough.
8. Web research is allowed (Claude Code WebSearch/WebFetch, Codex web search). Cite the source URL and date for every capability, price or benchmark claim, and separate vendor claims from independent measurements.
9. Report at the end: what you changed (file list), what you measured (numbers), what you recommend, what you did not do and why. Mark your orchestration task done through the app protocol only after the report.
