## REOPEN: idea-autopilot, the failing scenario for the next batch

**I2: the idea autopilot's agent tabs steal the owner's focus.** Owner, for dispatch-no-focus-steal: "whenever you dispatch a tab, my focus goes there … by default not", and that item's text covers "any other agent-opened tab".
- **Setup:** `scripts/smoke-verify-vr4-idea.mjs`. The owner's active tab is a coworker tab; the coworker calls `ideas.run({dryRun:true})`; the owner approves and fires the schedule. `.pane-tab.active` is sampled every 250 ms.
- **Result:** the active tab moved to the planner tab and to each of the three stage tabs as they opened, 62–65 samples in all. Reproduced 2/2 in runs 2 and 3; run 1 is not counted because of a harness flaw.
- **Control:** the same sampling on the same build shows 0 moves for `tabs.open`, `router.dispatch`, `agents.handoff` and `ideas.work` (F1, F2).
- **Cause:** `src/main/idea-runs/register.ts:105` opens every idea-run tab through `control.ownerScope(...)` with `tabs.open` and no `focus`. `src/main/agent-control.ts:877` forwards `focus` for an owner scope only when it is given, so the renderer's owner default brings the tab to the front.
- **Test to write:**
  - idea-run tabs (planner and stages) open with `focus:false`;
  - more generally, any internal owner-scope opener (schedules, durable jobs, idea runs) opens in the background unless the owner clicked.
  - Acceptance: I2's `activeTabMoves` is 0.

## Harness FAILs (not product failures; fixed and re-run)

- **A4 run 1:** my host used `spawnSync` for the client, which blocked the MCP server in the same process (a deadlock). I killed my own pids and switched to an async spawn, and run 2 passed.
- **R1 run 1:** it measured Codex through the fake exe's invocation log, which misses a version the adapter refuses before it spawns. It now reads the tab's `runtimeVersion`. The profile DB showed the refusal message, and run 2 passed.
- **F2 run 1:** `agents.handoff` was refused with "Choose a model from models.list" because the controller tab had no listed model. The fix is VR3 M1's setup (`claude-fable-5-1`), and run 2 passed.
- **L1b control run 1:** batch-delivery needs run inputs. The control moved to a second change on task-triage and passed.
- **I2 run 1:** it read the owner's tab before the click landed, and its timeline regex expected "Denied by owner" where the actual line is "Denied by Owner control". Both are fixed, and the result is not counted.
