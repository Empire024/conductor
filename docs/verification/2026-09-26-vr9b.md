## Findings (none reopen the item)

1. **Gap 2 leak, unchanged (INFO).** When the CLI cannot drop a rule live, a superseded tab that took a session rule at
   launch still accepts a turn and runs the approved external call (V3b, 2/2). This only happens with
   `apply_flag_settings` unsupported or the runtime disconnected. It does not stop the successor from running it.
   Closing it would mean restarting (or disposing) the superseded runtime when its grants move.
2. **Two live views before an answer (cosmetic).** When a successor re-hits a moved denial, it shows a second card with
   live buttons that reads like a fresh "Auto mode refused Bash" card. The service's own "refused this call again; it is
   the one already asked about" wording is not what the card renders. It is one request, and one click settles both
   (V1, V2), so the owner cannot approve twice. They may still think they are being asked twice.
