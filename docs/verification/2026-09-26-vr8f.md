## Findings for the next batch

1. **S3 (REOPEN), classifier-denial cards do not move.** A denial request is only built lazily in
   `PermissionGrants.pendingRequest` when the owner answers, so `transfer` never sees it. The next batch can turn S3 into
   a test: A's classifier denies a call, A hands off with `successor:true`, and then:
   - B's `permissions.list` holds it, or at least A's card names B;
   - approving it tells **B**, and B runs it once;
   - closing A does not lose it.

   One option is to materialize pending denial requests from the tab's unanswered denial notices in `transfer`.
2. **Chain titles (cosmetic).** Every successor is titled "<first title> (continued)" (agent-control.ts:1855). In
   A→B→C, B's moved card reads "Moved to <B's own title>". The routing is right, but the owner cannot tell B from C by
   the card.
3. **Gap 2 leak, as declared.** A CLI that cannot drop a rule live keeps a session rule after the handoff, so the
   superseded tab can still run an external call (S3b, 2/2). It only applies when `apply_flag_settings` is unsupported
   or the runtime is not connected.
