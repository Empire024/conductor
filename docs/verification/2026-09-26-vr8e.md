## Edit-then-run: is it wider than what an Auto worker may do?

Answered from the code; no smoke was run.
- `package.json` is not among the sensitive files (`approval-review-routine.ts:34`), so an Edit of its `scripts`
  counts as a routine workspace edit. So does a Write of a test file or any other script file.
- `scriptClass` (`approval-review-routine.ts:91-103`) re-reads package.json when `npm test` is asked. It checks the
  script **text** (install/publish/fetch patterns, owner-only reach, local class). It does not check the files that
  the script then runs.
- So an auto-allowed edit followed by an auto-allowed `npm test` runs code the worker wrote, and no reviewer turn
  happens anywhere in that chain. Asking directly for `node that-file.mjs` is still reviewed.
- **Plainly: it is not wider than Auto.** An Auto worker edits workspace files without a prompt, and `npm test` is the
  standard command Auto runs. It **is** wider than Ask-under-review before FX37. A wizard's Ask-mode coworker is now
  equal to Auto for running code through the project's test/build/lint scripts. AGENTS.md keeps a lower
  `exactPermission` for "an agent that cannot be trusted at all"; for that agent, the reviewer no longer sees what
  `npm test` executes. This matches FX37's specification ("what an Auto worker would simply run"). Whether it is
  acceptable for an untrusted agent is the owner's decision, not a defect.
