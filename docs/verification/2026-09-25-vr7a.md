## Reading docs/mac-node.md "Packaging and updates, unsigned" as the owner

- **Can they install the first build?** Yes, once a release carries Mac files. The steps are right, and S1b ran
  them: a quarantined dmg, the drag, and `xattr -dr com.apple.quarantine`. After that the app launches and verifies.
  No release carries Mac files today, so the first dmg exists only after someone dispatches `release.yml` with
  `mac` ticked (G1). The doc says so.
- **Can they receive the next one from it?** The update mechanism works: S1 went from 0.1.90 to 0.1.91 through
  the app's own updater, and S1b checked the GitHub feed. But only a release dispatched by hand from the Actions
  page with `mac` ticked carries a Mac build. `git.ship({publish:true})` and the Source control Publish switch
  never set it (S3c). If the owner publishes the way AGENTS.md prescribes, the installed Mac app keeps reporting
  "The latest release has no Mac build yet." The doc states this, so it is not a defect in this item. It is a gap
  in "receive the next one", though. **Follow-up for the controller:** a `mac` option on `git.ship` publish / the
  Publish switch, or have publish tick it once a Mac install exists.
- Still unconfirmed (the doc says so as well): the App Management prompt when an update replaces
  `/Applications/Conductor.app` in the owner's own session (G2). The GitHub-provider **download** path is also
  unconfirmed on a Mac. Its "no Mac build" branch is proven (S1b), and the download itself only through a generic
  loopback feed (S1).
