# Agent control and live project edits

Conductor exposes a first-party internal JSON protocol over an ephemeral loopback HTTP port. This implements feature 17 without changing the provider MCP policy. The server belongs to the app; there are no per-tab MCP processes or third-party configuration changes.

The first prompt of each native runtime receives a short briefing with the endpoint, a random per-conversation bearer credential, and `tools.list` discovery; it is sent again after a resume, a reconnect or a context compaction, never on every turn (see `docs/context-accounting.md`). Requests are `POST /control`, `Content-Type: application/json`, `Authorization: Bearer <credential>`, with a body of `{ "method": "tabs.list", "args": {} }`. Replies contain either `result` or `error`. Never print credentials in reports or blindly retry a mutation after a timeout. The briefing directs agents to use visible Conductor tabs when delegating to another provider.

The authority is the registered native conversation, its project, and its active workspace. An agent cannot substitute another project or workspace, operate on a hidden session, or control itself or any ancestor. Persistent parent relationships use the existing settings store, so busy collaboration logs cannot erase cycle protection. Collaboration handoff messages provide the audit trail. A human can release a relationship from the visible connection strip. Destructive tab closure and forgetting an agent memory require a native owner confirmation dialog; a request argument cannot grant approval. Human-authored memories cannot be forgotten or merged into by agent writes.

The endpoint binds only to `127.0.0.1`, checks its exact Host header, rejects browser Origin requests, accepts only authenticated JSON POSTs, and limits bodies to 3 MiB. Each credential may hold at most eight in-flight requests (a ninth receives `429`). Read-only and waiting methods — discovery/list/status reads, agent snapshots/history/artifacts, files reads, usage limits, repository/update status, and durable-job reads — run concurrently, including while a mutation is in flight. Mutations remain serialized in arrival order per credential, so one caller cannot race its own state changes. Closing a workspace/tab revokes its authority; moving saved history to a different workspace rotates its credential. History moves preserve the native session ID and permission settings and cannot cross projects or steal a conversation still open elsewhere. App control is disabled entirely in the explicitly isolated live acceptance suite. Codex's existing third-party MCP isolation and Claude's configuration policy remain unchanged.

## Tool surface

`tools.list()` returns signatures on demand, avoiding a large repeated tool catalog in every prompt.

| Family | Methods and principal arguments |
| --- | --- |
| State and models | `app.state()`, `models.list()`: resolved project/workspace, scoped open tabs, persistent relationships, available native providers and per-model effort choices. Runtime-discovered catalogs take precedence over configured fallbacks; the source is explicit. |
| Tabs | `tabs.list()`, `tabs.open({kind?, provider?, model?, effort?, title?, repository?, research?})`, `tabs.focus({tabId})`, `tabs.rename({tabId,title})`, `tabs.split({tabId,direction})`, `tabs.detach({tabId})`, `tabs.close({tabId})`. Open kinds include native agents, terminals, browser, file tree, tasks, memory, routines and logs; files use `files.open`. `repository` and `research` open a `local` tab with its per-conversation grants already on, under the `agents.grant` rules below. |
| Native agents | `agents.list()`, `agents.snapshot({agentSessionId})`, `agents.history({agentSessionId,afterSequence?})`, `agents.submit({agentSessionId,prompt})`, `agents.steer({agentSessionId,prompt})`, `agents.interrupt({agentSessionId})`, `agents.resume({agentSessionId})`, `agents.fork({agentSessionId,title?})`, `agents.release({agentSessionId})`, `agents.grant({agentSessionId,repository?,research?})`. Native sessions own dispatch, approvals, streaming, steering and history. `agents.grant` switches a `local` coworker's repository-writes (`localGit`) and deep-research (`localResearch`) grants from outside it, so a non-local coworker can open a local tab, grant it what the job needs and hand it delivery work without the owner clicking. It writes the conversation's durable settings through the composer's own path, so that tab's toggles show the change and the local runtime enforces it at dispatch exactly as before; it applies from the next turn. Only a non-local caller may grant, only to a `local` tab it already controls on this machine, never itself or an ancestor, and never a conversation a paired machine drives; `false` revokes, an omitted field is left alone, unknown keys are refused, and the result reports what is now on and off. A local model cannot call it: the sandbox's `conductor` tool allowlist does not include it. `agents.steer` does what the composer does with a message (`StructuredSessions.steerOrStart`): while a turn is running or waiting on an approval or question it steers the message into that turn where the provider can, else queues it behind the turn; while the conversation is idle, finished, failed, disconnected or interrupted it starts a turn exactly as `agents.submit` does — one turn, the conversation's own settings, the same control link; while a turn is still stopping (`interrupting`) it is refused so it cannot race the stop. The result carries `delivery: "started"` or `"queued"`. Before this, a steer into an idle or interrupted conversation was refused with "There is no active turn to queue behind" although discovery promised composer behavior. |
| Files | `files.list({query?})`, `files.read({path})`, `files.open({path})`, `files.write({path,content,expectedContent})`. Search reuses the indexed project search. Paths must remain inside the canonical project root, including junction targets. Text reads/writes are bounded to 1 MiB; writes use an exact previous-content comparison, with `null` for exclusive creation, and honor coworker edit leases. |
| Checklist | `tasks.list()`, `tasks.update({revision,id,status?,title?})`: updates feature-list.md through its existing optimistic revision API, keeps stable task markers and preserves other agents' active claims. |
| Memory | `memory.recall({query?})`, `memory.remember({gist,kind?,cues?})`, `memory.forget({id})`. New memories are always agent-authored; human memories remain separately owned. |
| Orchestration | `orchestration.snapshot()`, `orchestration.tasks.create({title,description?,priority?,status?,assignedAgentId?})`, `orchestration.tasks.update({id,...})`, `orchestration.routines.save({id?,name,description?,steps})`. Existing project-level stores validate all agent/task references. |
| Workspace | `workspace.rename({title})`. |
| Delivery | `git.status()`, `git.ship({message,paths?,publish?,waitSeconds?})`, `git.ship.status({runId?,waitSeconds?})`. `git.ship` runs on the host with the owner's own Git credentials and network — the sandbox never has to reach GitHub: preflight, `npm test`, `npm run build` (in an isolated worktree when `paths` is a subset of a dirty tree) and a local commit; nothing is pushed and no release is built. Only `publish: true` — the owner, a wizard tab or a controller publishing a finished batch, never a dispatched coworker — also pushes (one `pull --rebase` retry on a non-fast-forward), starts the release workflow and checks the release carries the installer, blockmap and `latest.yml`; a failed release run's annotations come back in the error. App control passes `publish` through to `delivery.ts` exactly as the Source control panel's Publish switch does (it used to validate the flag and then drop it, so an agent's publish silently made a local commit). Cloud coworkers ship without a dialog because the project's delivery contract already requires it; a local model needs the owner's confirmation, and the dialog says which of the two it is asking for (a local commit with no push and no release, or a push and a published release); read-only and planning turns cannot ship. `waitSeconds` (max 100, under the control server's request timeout) long-polls. The Source control panel in the left rail runs the same pipeline for the owner and shows deliveries agents started. Per-project overrides live in `.conductor/delivery.json`. |
| Usage | `usage.limits({provider?})`: a zero-turn read of the newest account allowance each provider reported. `StructuredSessions` folds every provider usage event that carries `rateLimits`/`rateLimitsByLimitId` into one small settings row (`usageLimits.latest`, at most 32 buckets per provider), so the read never touches the event journal and survives a restart. Claude buckets are its `rate_limit_event` windows (`five_hour`, `seven_day`, the Fable weekly model window); Codex buckets are limit ids with primary/secondary windows, merged across sparse updates, plus credits and plan type. Each window gives `usedPercent`, `windowMinutes`, `resetsAt`, `observedAt`, `ageSeconds` and the reporting conversation (named only inside the caller's project). A window whose `resetsAt` has passed says `state: "reset"`; a provider with nothing recorded, or that reports no allowance at all (Grok reports token spend and context only), says `status: "unknown"` with the reason in `unknown`. It is on the local-model `conductor` allowlist with only `provider` as an argument. |
| App updates | `app.update()`, `app.update.status()`, `app.update.authorize({agentSessionId,allowed?})`. `app.update` runs the existing `npm run update:local` pipeline on the host and publishes into the installed app's local feed, so the app offers "Update pending"; no installer is ever launched. It returns immediately and the build is polled with `app.update.status`. A native (non-local) coworker in Auto builds without asking: the build only offers "Update pending", and installing it stays with the owner or a wizard tab. A local model, and any tab below Auto, needs the owner's confirmation for each build, unless a non-sandboxed coworker cleared that conversation with `app.update.authorize` — a clearance that lives in memory only and lapses when the granting tab closes. Only a Conductor checkout on Windows can be built. |
| Router | `router.start({prompt,provider?,model?})`, `router.dispatch({tasks:[{title,prompt,provider?,model?,effort?,permission?,exactPermission?,repository?,research?}]})`. A dispatch contains one to four independent assignments. A worker whose prompt was refused before any turn began (no user message, no active phase) has its tab closed, its control link released and its orchestration task removed; its result keeps the error and says `tabClosed`. A worker that did or may have received its prompt keeps its tab, and its task is marked blocked. |
| Local model servers | `local.servers()`, `local.stop({model?,pid?,force?})`. `local.servers` lists the llama.cpp servers running on this machine: model, pid, port, start time, `startedByConductor`, and this project's conversations on each with their phase and whether one is mid-turn. `local.stop` stops one server this Conductor started, named by model (the `local/` prefix is optional) or pid; it is refused while a turn is using it (a conversation mid-turn here, or llama.cpp's slots generating) unless `force:true`, which asks the owner first (a wizard tab or the owner credential is not asked) and fails that turn. A server Conductor did not start is never stopped, and a sandboxed local conversation cannot stop one. The next local turn starts its server again. |
| Scheduled tasks | `schedules.list()`, `schedules.get({taskId})`, `schedules.create({name,prompt,everyMinutes?,timing?,urgent?,agent?,churnModel?,brain?,enabled?})`, `schedules.update({taskId,...})`, `schedules.pause/resume/runNow({taskId})`, `schedules.delete({taskId})`, `schedules.scripts.save({taskId,name,content,language?,format?,runWhen?,timeoutSec?,order?,description?})`, `schedules.scripts.delete({taskId,name})` (src/main/schedule-control.ts, docs/schedules.md). An agent sets up recurring work when the owner asks: the task defaults to the caller as its assigned agent, and the agent writes the task's deterministic scripts. Reading is open to the project; pausing, resuming and running now to any writable non-local conversation; changing the goal, agent or scripts to the owner, a wizard tab or the task's maintainer (its creator, or the conversation the owner assigned its scripts to from the panel); deleting asks the owner unless the owner or a wizard tab asks, and built-in tasks can only be paused. A sandboxed local model changes nothing here, because a script runs on the host unattended. |
| Owner credential | Every launch writes `control-owner.json` beside the app's data (`%APPDATA%\Conductor`, or `CONDUCTOR_TEST_USER_DATA` for a test profile) with the endpoint, a bearer token, the pid and version, owner-only file permissions; the file is removed when the control server closes. A process on this machine that reads it acts with the window's authority: it names a project and workspace per request (`{"method","args","scope":{"projectId","workspaceId"}}`, defaulting to the first open ones), gets every method above without confirmation dialogs, opens native coworkers on Auto, may steer any tab, and additionally has `projects.open({path,name?})`, `app.update.check()`, `app.update.download()`, `app.update.install({force?})`, `app.restart({force?})` and `app.quit.confirm({stopWork})`. A restart or install it starts itself is forced unless it passes `force:false`: running work is stopped without the "Work is still running" dialog and dirty editors are flushed into their recovery drafts. `app.quit.confirm` answers that dialog when some other path raised it (the owner quitting, a `force:false` restart): `app.state` shows it as `pendingQuitConfirmation` (`{action,running,openedAt}`) while it is open, `stopWork:true` stops the work and goes ahead, `false` cancels, and the first answer wins, the owner's click or the agent's. It has no conversation, so `agents.handoff` is refused. This is what `scripts/overseer.mjs` (docs/overseer.md) runs on, outside the app, so that it survives the restarts it triggers. |
| Wizard tabs | The wand toggle in the composer (`settings.wizard`, replacing the former "Review coworkers" button; the old setting is still honored for review alone) gives a conversation on a frontier model (`isFrontierModel`: Claude Opus or Fable, GPT-6 Astra) the same authority as the owner credential, in its own tab: `AgentControl.call` marks the scope `wizard` from the durable settings on every call. It keeps its tab, links and attribution, opens coworkers on Auto with `continueOnLimit`, may steer a tab another agent controls, needs no confirmation dialog, gets the owner-only methods, and its coworkers' approval requests go through the stronger-model review as the old opt-in did. After a restart, only the wizard tab that started it (`app.restart`, `app.update.install`) is resumed and sent a continuation prompt; an owner restart resumes none. A wizard that cannot or should not restart itself calls `app.restart.request({reason})` instead: the owner's update control shows "Restart requested by <tab> — <reason>" (a restart button of its own when no update is waiting), `app.state` shows it as `restartRequest`, and the next launch, however the owner restarts, resumes that wizard like a self-started one. A request lasts until that launch or 24 hours, and a newer one replaces it. Conversations that were idle at the restart keep their settled phase and reconnect their native conversation on the next message; only a turn that was in flight comes back `disconnected`. A wand on a lesser model, or in read-only or planning mode, is inactive (`wizardActive`). |
| Tool output | `agents.artifact({agentSessionId,artifactId})` returns the full text of a tool output whose history event only carries a tail (`outputArtifactId`), up to 2 MiB. |

Stable links use `conductor://<project>/tab/<encoded-tab-id>`, `/file/<encoded-path>`, or `/workspace/<encoded-workspace-id>`. Clicking a conversation link resolves its exact registered resource and focuses the correct main or detached window. It does not search filenames or use an external browser.

Read-only permission, a read-only execution sandbox, or planning mode blocks file/checklist writes and dispatch into writable conversations. Newly opened coworkers inherit the restriction: Codex uses its read-only sandbox; Claude and Grok use their planning mode; a local model uses its read-only permission, under which the local runtime offers no write tool and no `run_command` (it has no execution-sandbox mode to name, so dispatch sets `sandbox: "read-only"` only for a provider that advertises it). Delegated turns retain the target conversation's existing settings and appear as normal user messages and native output in the visible tab.

## Router and real-time edits

The router is an `OrchestrationAgent` with role `conductor-router` and a persisted `RoutineDefinition` named `Conductor router`. Starting it creates a routine run and an in-progress task, opens a real native agent tab, and submits the user's work plus concise coordination instructions. The router reads the model catalog, chooses provider/model/effort for bounded tasks, and calls `router.dispatch`. Each coworker has a visible tab, native session, persistent orchestration agent/task, and a controller link. The assigned agents update completion through the same task API; dispatch failures mark their tasks blocked.

Feature 18 adds project directory watches plus immediate notifications from protocol writes. Directory watches survive atomic file replacements. Clean open editors adopt current disk bytes and retain their view position. Dirty editors preserve the owner's buffer and its original comparison baseline, show a conflict, and offer the existing save-copy/reload paths. The checklist refreshes from the same file-change notifications. Its periodic refresh remains a fallback.

## Validation

`src/main/agent-control.test.ts` covers project/workspace authorization, hidden/closed sessions, own/ancestor control denial, persisted links after more than 200 collaboration messages, owner confirmations, canonical path/junction escapes, competing file leases, stale writes, human memory ownership, task claims, plan/sandbox restrictions, history workspace relocation, credential rotation, request authentication/origins/size, isolated-live-test refusal, and a router run using the real stores and `StructuredSessions` with a synthetic provider boundary.

`scripts/smoke-agent-control.mjs` runs the real Electron main process, preload, renderer, loopback endpoint and router. By default its synthetic Claude source controls a visible Codex router and coworker. It checks native user/output events, persisted orchestration state, detached-window links and exact URI focus, live protocol/external atomic saves, dirty editor conflicts, and owner link release. Provider subprocesses are fixed offline fixtures; the test performs no model inference. Test-only captured briefing credentials are deleted on exit. Run after `npm.cmd run build`; the result is written to `artifacts/agent-control/report.json`.

`agents.handoff({handoff,title?})` is the one `agents.*` method that takes no `agentSessionId`: a conversation hands off only itself, because nobody outside it knows what its remaining work is and emptying a coworker's context from outside would be a way to erase it. It exists for the context-cost nudge described in `docs/token-thrift-policy.md`: past a band of its window, a conversation writes that document's bounded handoff — `Objective`, `Constraints`, `Owned files`, `Verified findings`, `Remaining work`, `Artifact references`, each heading on its own line and in that order, 200 to 12,000 characters — and calls this method. A handoff missing a section, or carrying them out of order, is refused by naming the section, because the receiver opens with no other context and cannot ask for it later. The new tab is opened through the ordinary `tabs.open` path in the caller's workspace, on the caller's provider, model, effort and permission, so the same clamping applies and a read-only or planning conversation hands off to a read-only or planning one — which is why it is allowed to hand off at all. The handoff is submitted through the ordinary `agents.submit` path, so the receiver gets the normal first-turn briefing and its own credential, and a `handoff` collaboration message from the caller names the tab that took the work over. The caller is never interrupted or closed: it keeps its tab, its history and its steering rights over what it opened, and the result tells it to finish the step it is in and stop rather than continue in parallel.
